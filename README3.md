# notlang

[![tests](https://github.com/mahmudamen/notlang/actions/workflows/tests.yml/badge.svg)](https://github.com/mahmudamen/notlang/actions/workflows/tests.yml)

An experiment: **a programming language that humans don't write and don't have to read.**
Mizan programs are typed graphs generated by an AI, then checked and run by an interpreter.
Humans review the *intent* (spec and tests) and *audit* through a read-only viewer.

- Paper: [PAPER-001-ai-first-language.md](PAPER-001-ai-first-language.md)
- Spec: [SPEC-001.md](SPEC-001.md)
- Status: **v0.1, a toy.** It exists to test one claim: that the cheapest thing for an AI to emit can also be the safest.

## Try it (Python 3.9+, no dependencies)

```bash
# what does this program say? (read-only viewer)
python -m mizan view examples/partner_total.json

# run it; effects must be granted explicitly
python -m mizan run examples/partner_total.json --db examples/db.json --arg pid=1 --grant db.read

# forget the grant and the interpreter refuses to start
python -m mizan run examples/partner_total.json --db examples/db.json --arg pid=1

# a contract catches a bug: "debit must equal credit"
python -m mizan run examples/journal_balance.json --db examples/db.json --arg eid=2 --grant db.read

# a type error, reported as data an AI can repair from
python -m mizan check examples/bad_type.json --db examples/db.json

# the repair loop with a scripted stand-in for an LLM
python examples/repair_demo.py

# tests
python -m unittest discover -s tests -v
```

## Platforms

Pure Python, standard library only, so it is meant to run the same on Linux, macOS and Windows
(CI runs the tests on all three, Python 3.9 to 3.13). Programs are plain JSON, and function hashes are
identical on every platform.

On **Windows**, use `python` (or `py`) instead of `python3`, and set the API key like this:

```powershell
$env:ANTHROPIC_API_KEY="sk-..."
python -m bench.run_bench
```

(`ANTHROPIC_API_KEY=sk-... python ...` is bash-only syntax.)

## What's in v0.1

| Idea from the paper | In the prototype |
|---|---|
| Typed graph, no syntax | JSON graph of 22 ops; invalid shapes are rejected |
| No implicit conversions | `Int` and `Money` never mix; floats banned for money |
| Explicit effects | Declared exactly, granted by the host, checked before running |
| Contracts | `pre` / `post` checked at run time, failures carry the failing expression |
| Content addressing | Hash ignores node names, labels and money spelling |
| Machine-to-machine repair | Errors are structured JSON (`stage`, `code`, `node`, `detail`) |
| Human audit | `mizan view` |

## Benchmark seed (does a model actually write Mizan?)

`bench/` holds 10 small ERP-style tasks (invoice totals, journal balance, stock never negative, ...),
each with test cases, plus a harness that runs the repair loop and reports:
first-try accepted, accepted within the attempt budget, correct, and **incorrect-but-accepted**.

```bash
python -m bench.run_bench --mock                      # offline dry run, tests the harness only
ANTHROPIC_API_KEY=sk-... python -m bench.run_bench    # real model (default: claude-sonnet-5-5)
python -m bench.run_bench --model <model-id> --max-attempts 5 --out results.json
```

`--mock` is a scripted stand-in and says nothing about real models. The real-model path is a plain
HTTPS call to the Messages API using the standard library only. The paper's baseline ("AI writes Python plus
tests" on the same tasks) is not built yet.

## Layout

```
mizan/        interpreter (ops table, checker, runner, viewer, hashing, CLI)
examples/     programs, a sample database, and the repair-loop demo
bench/        task set, reference solutions, harness, mock and API model clients
tests/        unittest suite
```
